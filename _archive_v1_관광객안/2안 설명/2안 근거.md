## 1. 인벤토리가 만든 구조적 제약 ★

### ① 국적 축을 가진 데이터셋은 14종, 그중 대민개방은 8종

`02_데이터셋_인벤토리` 의 `세분화 축(디멘션)` 에 '국적' 또는 '내외국인'이 있는 것:

```
전체 86종 / 납품 확인 76종 / 대민개방 43종

국적·내외국인 축 보유 : 14종
  DS-014 017 022 024 026 027 028 030 032 033 034 038 042 046
  그중 대민개방 O     : 8종  (DS-014 017 022 024 026 027 028 030)
  그중 미납품          : 1종  (DS-042 — 관심지역 내/외국인별 방문인구, Q-18)
```

### ② 그런데 '국적 축 AND 업종 축'을 동시에 가진 데이터셋은 0종입니다

```
국적 축 AND 시간대 축 : DS-014 017 022 024 032 033 034   (7종)
국적 축 AND 업종 축   : 없음                              (0종)
업종 축 보유          : 24종  (그중 대민개방 6종: DS-047 048 065 066 067 069)
```

**이 한 줄이 원 기획을 정면으로 반박합니다.**
원안의 "외국인 다빈도 이용 업종"은 `02` 시트 기준으로는 산출 불가입니다.

### ③ 그러나 `03_컬럼사전`을 보면 DS-056에 `nt`(국적명칭)가 있습니다

| DS-056 | `GGC_SALES_YM_AMD` — 행정동별 내외구분 월별 집계 데이터 |
|---|---|
| 실제 헤더 (11컬럼) | `ta_ymd, cty_rgn_no, admi_cty_no, card_tpbuz_cd, card_tpbuz_nm_1, card_tpbuz_nm_2, card_tpbuz_nm_3, gb, nt, amt, cnt` |
| `gb` | 내외구분 — 01 내지인 / 02 인접지인 / 03 외지인 **(외국인의 경우 모두 외지인)** |
| `nt` | 국적명칭 — "외국인 국적코드 sheet 참조" (★그 sheet가 인벤토리에 없음) |
| 공간단위 | 행정동 |
| 보유 | **202501~202606 · 18개월 · 단일 구조** (구조변경 없음) |
| 용량 | 19.17MB/월 · 224,743행/월(경기 전역) · 총 0.324GB |
| 대민개방 | **X** (민감도 중 — 비개방 집계) |
| 분석 난이도 | **하** — pandas 즉시 가능 |

**결론** — DS-056은 인벤토리 요약 축(`세분화 축`)에는 드러나지 않지만
**86종 중 유일하게 국적 × 업종 × 동 × 소비를 동시에 갖는 데이터셋**입니다.
2안 전체가 이 한 종 위에 서 있습니다.

> 인벤토리 수정 제안: `02` 시트 DS-056의 `세분화 축(디멘션)` 이 현재 "업종"뿐입니다.
> **"업종, 내외구분, 국적"** 으로 보정해야 다음 사람이 이 데이터를 찾을 수 있습니다.

### ④ 국적 축은 6개월, 시군구 축은 17개월

| DS | 공간 | 보유 | 개월 | 특이사항 |
|---|---|---|---|---|
| DS-026 | 행정동 | 202601~202606 | 6 | 202604부터 5→6컬럼 (Q-13) |
| DS-017 | 행정동 | 202601~202606 | 6 | 단일 구조 |
| DS-028 | 행정동 | 202601~202606 | 6 | 단일 구조 |

2025년에는 **행정동 단위 외국인 데이터가 존재하지 않습니다**(Q-04).
2025년은 시도·시군구 단위뿐이고, 행정동 단위는 2026년부터입니다.

→ **국적별 동 지도는 6개월치로만 만들 수 있고 계절성 판단은 불가능합니다.**
반면 소비(DS-056)는 18개월이므로, 시계열은 소비 쪽에서만 나옵니다.

### ⑤ 공간 해상도 — 국적이 있으면 동, 블록이면 국적이 없다

```
국적 보유 + 행정동   : DS-017 · 026 · 028 · 056
국적 보유 + 블록/셀  : DS-032(50m, 639GB, 개방X) · DS-033(120GB)
                       단 FORN_GB(내/외국인 구분) + 단기외국인수 S99 뿐, 국적코드 아님
블록 단위 카드       : DS-048 049 050 052 053 054 058 059 — 전부 국적 없음
```

**결론** — 「국적별 × 100m급」 데이터는 86종 안에 없습니다.
2안의 최소 공간단위는 **행정동(25개)** 이고, 이것은 우회가 아니라 구조적 한계입니다.
화면에서 동 레이어와 블록 레이어의 해상도가 다름을 범례로 명시합니다.

### ⑥ 계산은 비개방분으로, 화면은 집계 결과만 — 2층 구조

```
2안 핵심 데이터의 대민개방 여부
  DS-026  O    DS-017  O    DS-048  O    DS-047  O
  DS-056  X  ← 척추가 비개방
  DS-050  X    DS-054  X
```

DS-056이 비개방(민감도 중)이므로 **금액 원본을 시민 화면에 띄울 수 없습니다.**
분위·배수·순위만 노출합니다. 3안이 DS-032·054로 같은 구조를 택했습니다.
이건 우회가 아니라 인벤토리 민감도 등급이 요구하는 정상 절차입니다(Q-17).

## 3. 파라미터 등급

> 등급 기준은 3안·4안과 같습니다.
> **A** 보유 데이터로 직접 산출 · **B** 데이터로 타당성 확인 + 판단 혼입 ·
> **C** 근거 없음 · **X** 근거 불필요(시민이 정하는 값)

| # | 파라미터 | 값 | 등급 | 근거 / 해소 조건 |
|---|---|---|---|---|
| 1 | 점수 결합 방식 | `min` (AND) | **A** | 3안·4안 가중합 실측 실패 전례 (경로 98% 변동 / 집결지 50~85% 변동) |
| 2 | 소비 정규화 | LQ (입지계수) | **A** | Q-21 절대값 금지 → 비중의 비중만 허용 |
| 3 | 마스킹 임계 | `cnt < 5` | B | 인벤토리 민감도 판단 근거 "소표본 구간 마스킹 권장". 실데이터 분포 확인 후 조정 |
| 4 | 참고값 구간 | `cnt 5~29` | B | 동일 |
| 5 | 국적 목록 | 관측·기준 통과분만 | **A** | DS-026 `cntry_nm` 실측 |
| 6 | 체류 유형 분리 | 장기(1)/단기(2) | **A** | `in_forn_div_nm` 코드 정의 |
| 7 | 시간대 정합 | DS-017을 DS-047 버킷으로 내림 | B | DS-047 `hour` 는 2시간 단위 + `hour='01'`=7시간 |
| 8 | `hour='01'` 처리 | **계산에서 제외** | **A** | 07 코드값사전 — 00:00~06:59 (7시간). 3안과 동일 대응 |
| 9 | 업종 그룹 | 7개 목적군 | **C** | ★ 카드 업종코드 전체 목록이 없음 (요청서 A-보조3) |
| 10 | 동선 스톱 수 | 2~3 | X | 시민이 고르는 값 |
| 11 | 동→동 연결 임계 | OD 관측 하위 절단 | **C** | DS-004·005 실데이터 분포 확인 후 결정 |
| 12 | 객단가 순위 구간 | 동·업종 내 분위 | B | 표본 편향 회피 목적. 절대값 미사용 |
| 13 | 관광 축 채택 임계 | 미정 | **C** | DS-001 목적=4 유입 규모 실측 후 결정. 미달 시 **축 폐기** |
| 14 | 국적 집중도 임계 | 미정 | **C** | DS-026 실측 후 결정. 집중 없으면 **2안 전제 반박** |

**등급 분포 — A 5 · B 4 · C 4 · X 1**

C등급 4개는 전부 **주 데이터가 없어서** 정할 수 없는 값입니다.
DS-056·026·004 와 업종코드표가 들어오면 4개 모두 A 또는 B로 확정됩니다.
즉 2안의 C등급은 설계 결함이 아니라 **데이터 미수급 상태의 표현**입니다.

> 대조: 같은 시점 3안은 파라미터 12개 중 C 2개, 4안은 23개 중 C 14개였습니다.

## 4. Phase 0 — 데이터 도착 직후 반드시 먼저 볼 3가지

이 셋을 통과하지 못하면 2안은 설계를 바꾸거나 폐기합니다.
**순서를 바꾸지 마십시오.** 1번이 실패하면 2·3번은 의미가 없습니다.

### ① 국적 집중도 — 2안의 생사

```sql
-- DS-026, 안산, 장기(1)
SELECT CNTRY_NM,
       MAX(pop_share) AS top_dong_share,
       COUNT(*)       AS n_dong
FROM (SELECT CNTRY_NM, ADM_CD,
             SUM(POP) / SUM(SUM(POP)) OVER (PARTITION BY CNTRY_NM) AS pop_share
      FROM ds026
      WHERE SGG_CD LIKE '4127%' AND IN_FORN_DIV_NM = '1'
      GROUP BY 1, 2)
GROUP BY 1 ORDER BY 2 DESC;
```

**판정** — 상위 1개 동 점유율이 **0.25 미만인 국적이 대부분**이면
국적별 지도는 성립하지 않습니다(25개 동 균등 분포 = 0.04).
그 경우 국적을 **권역군(동북아 / 동남아 / 중앙아 / 기타)** 으로 묶어 재시도하고,
그것도 안 되면 국적 축을 버리고 '외국인 전체' 단일 축으로 축소합니다.

### ② DS-056 국적 셀의 희소성 — 계산 가능성

DS-056은 경기 전역 224,743행/월입니다. 안산(4127*) 몫은 약 9천행/월 수준으로
추정되는데, 그 안에서 `업종소분류 × gb(3) × nt(최대 22)` 를 다 채우려면
동당 수천 조합이 필요합니다. **대부분 비어 있을 가능성이 높습니다.**

**정황 증거** — `04_규격_실측_비교` 시트에 실린 DS-056 실제 샘플 1행의 `cnt` 가
**2** 입니다.

```
20260501, 41271, 41271510, D01003, 소매/유통, 가전제품, 컴퓨터/주변기기, 02, 000, 7220149, 2
                                                                                          ↑ cnt=2
```

인벤토리 작성자가 특별히 고른 행이 아니라 대표 확인 파일의 첫 행입니다.
3중 세분화(업종소분류 × 내외구분 × 국적) 구조상 **셀당 건수가 한 자릿수인 것이
일반적일 수 있다**는 뜻이고, 그렇다면 `cnt >= 5` 마스킹만으로도 데이터의
상당 부분이 사라집니다. 이 검증을 계산보다 먼저 두는 이유입니다.

```sql
SELECT COUNT(*)                                  AS cells,
       SUM(CASE WHEN cnt >= 5  THEN 1 ELSE 0 END) AS usable,
       SUM(CASE WHEN cnt >= 30 THEN 1 ELSE 0 END) AS solid
FROM ds056
WHERE cty_rgn_no LIKE '4127%' AND nt <> :domestic_code;
```

**판정** — `usable` 이 동·업종 조합의 **10% 미만**이면
업종을 소분류에서 **중분류로 올리고**, 월을 **3개월 이동합**으로 묶습니다.
그래도 안 되면 국적을 권역군으로 묶습니다. 완화 순서: **업종 → 시간 → 국적.**
국적을 가장 마지막에 묶는 이유는 그것이 2안의 유일한 차별점이기 때문입니다.

### ③ 장기/단기 비율 — 관광 축 채택 여부

```sql
SELECT SUM(CASE WHEN IN_FORN_DIV_NM = '2' THEN POP END) / SUM(POP) AS short_share
FROM ds026 WHERE SGG_CD LIKE '4127%';
```

단기 비중이 낮으면(예상) **관광 탭을 만들지 않고** 정주 외국인 중심으로 확정합니다.
DS-001의 `PURPOSE=4`(관광) 서울→안산 유입 규모로 교차 확인합니다.
